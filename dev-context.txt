# Contexte de Développement (GUI/TUI/CLI) - Debian NVIDIA Driver

Ce document sert de mémoire de projet pour éviter les régressions lors des évolutions GUI, TUI et CLI.
Il est volontairement détaillé.
Dernière mise à jour: 2026-06-30 (driver latest 610, GBM Debian, suspend/resume, version 1.2.2).

## 1) Architecture actuelle (source de vérité)
- Backend métier unique: `debian-nvidia-all-cli.sh`
- Frontend terminal: `debian-nvidia-all-tui.sh`
- Frontend graphique: `ui/app.slint` + `src/main.rs`

Principe clé:
- Toute logique métier (dépendances, privilèges, détection/choix runfile, règles de version) doit vivre dans la CLI.
- TUI/GUI orchestrent et affichent, sans dupliquer le backend.

## 2) Répartition des responsabilités

### 2.1 CLI (`debian-nvidia-all-cli.sh`)
La CLI est la couche métier et technique principale.

Responsabilités:
- Vérification/installation des dépendances système.
- Gestion des privilèges (élévation root) centralisée.
- Installation de `spdx-licenses` et `pacstall`.
- Sélection runfile local ou en ligne.
- Génération pacscript final + exécution `pacstall`.
- Exposition d'API "machine-readable" consommables par TUI/GUI.
- Filtrage GPU optionnel via `--gpu <modele>` pour la sélection de version online.

Fonctions importantes:
- `run_as_root`:
  - stratégie: `sudo` -> `pkexec` -> prompt GUI (`zenity`/`kdialog`) -> `sudo -S`
- `check_dependencies`:
  - étape 1/3: outils système
  - étape 2/3: `spdx-licenses`
  - étape 3/3: `pacstall`
- `inspect_dependencies_cli`:
  - inspection sans installation, sortie machine-readable
- `print_versions_cli`:
  - expose recommended/latest/legacy pour la GUI
- `print_local_runfiles_cli`:
  - expose la liste des runfiles locaux valides

Hardening ajouté:
- Si `/tmp/pacstall` est un fichier:
  - suppression puis recréation dossier `/tmp/pacstall`
  - fallback avec `run_as_root` si permissions insuffisantes.

### 2.2 TUI (`debian-nvidia-all-tui.sh`)
Le TUI est une façade UX terminale.

Responsabilités:
- Menus, navigation, aide à la saisie, résumé lisible.
- Appel de la CLI pour toute action métier.

Le TUI délègue désormais à la CLI:
- check dépendances (`--inspect-dependencies`, puis `--check-dependencies` après validation)
- runfiles locaux (`--print-local-runfiles`)
- installation finale

Comportement dépendances au lancement:
1. Inspection via `--inspect-dependencies`
2. Affichage des manques
3. Confirmation Oui/Non
4. Validation Entrée explicite avant installation dépendances
5. Installation via `--check-dependencies`

UX actuelle TUI:
- `b` (back) disponible sur tous les menus sauf première page.
- `q` (quit) formaté dans l'aide à la saisie.
- Aide à la saisie colorée:
  - lettres/touches en bleu
  - `Entree` en vert
  - `ANNULER` en rouge
- Première page:
  - cache l'option locale si aucun runfile valide détecté
  - message clair à l'utilisateur (pas de crash)
- Menu module noyau orienté utilisateur:
  - `auto`
  - `proprietaire`
  - `open-kernel-module`
  - mapping interne vers CLI:
    - `proprietaire` -> `--nvidia-open false`
    - `open-kernel-module` -> `--nvidia-open true`
- Résumé:
  - affiche des libellés métier (pas d'ID interne type `Action: 2`)

### 2.3 GUI (`ui/app.slint` + `src/main.rs`)
La GUI est une façade graphique moderne sur la CLI.

Responsabilités:
- Affichage, sélection profil, lancement, logs, statut.
- Orchestration asynchrone des appels CLI.

Ne fait pas:
- logique métier dépendances/version/root en local.

Variables d'environnement GUI:
- `NVIDIA_GUI_HELPER`:
  - chemin absolu/relatif vers un script CLI alternatif à utiliser comme backend.
  - utile pour tests locaux et scénarios de dev.
- `NVIDIA_GUI_TEST_MISSING_DEPS`:
  - si `1|true|yes|on`, force la simulation de dépendances manquantes côté GUI
  - permet de tester le pop-up dépendances sans modifier l'état réel de la machine.

## 3) CLI: options publiques à connaître

Options importantes utilisées par TUI/GUI:
- `--help`
- `--self-test`
- `--check-dependencies`
- `--inspect-dependencies`
- `--print-versions`
- `--print-local-runfiles`

Comportement CLI:
- sans argument -> affiche `--help` puis quitte.

## 4) Flux GUI détaillé (actuel)

### 4.1 Démarrage GUI
- Rust résout le chemin helper (`debian-nvidia-all-cli.sh`) via:
  - env `NVIDIA_GUI_HELPER`
  - chemins candidats (repo/exe/cwd)
- Thread asynchrone `--print-versions` pour alimenter les profils.

### 4.2 Au clic "Lancer l'installation"
1. Étape log `[step 1/4]` résolution backend
2. Étape log `[step 2/4]` inspection dépendances (`--inspect-dependencies`)
   - si `NVIDIA_GUI_TEST_MISSING_DEPS` est actif: simulation de manques pour forcer le pop-up
3. Si dépendances manquantes:
   - pop-up modal affiché (Oui/Non)
   - détails listés dans logs et message popup
4. Si user clique Non:
   - fermeture popup
   - statut: `Interrompu`
   - retour état initial (pas de lancement)
5. Si user clique Oui:
   - lancement backend dans PTY (`script`)
   - commande:
     - `bash helper --check-dependencies && bash helper --source online ... --action 1`
6. Streams `stdout`/`stderr` lus en asynchrone, ANSI nettoyé, logs live.

### 4.3 Pop-up dépendances (Slint)
- Propriétés UI:
  - `dep-popup-visible`
  - `dep-popup-message`
- Callbacks:
  - `dep_popup_yes()`
  - `dep_popup_no()`

## 5) Contrat d'intégration TUI/GUI -> CLI

### 5.1 Sortie de `--inspect-dependencies`
Format texte clé=valeur:
- `MISSING_TOOLS=`
- `MISSING_PACKAGES=`
- `MISSING_SPDX=true|false`
- `MISSING_PACSTALL=true|false`
- `HAS_MISSING=true|false`

### 5.2 Sortie de `--print-versions`
Format texte clé=valeur (utilisé GUI):
- `RECOMMENDED=`
- `LATEST=`
- `LEGACY580=`
- `LEGACY470=`
- `LEGACY390=`
- `LATEST_SUPPORT=`
- `DETECTED_GPU=`

Cas d'erreur à gérer côté front:
- `ERROR=Network` (aucun miroir/version récupérable)
- `ERROR=NoVersions` (source répond mais aucune version exploitable)

### 5.3 Sortie de `--print-local-runfiles`
- une ligne par runfile valide (nom de fichier)

## 6) Détails UX importants (non-régression)

### TUI
- Première page doit rester simple pour néophytes:
  - `Recherche et telechargement en ligne`
  - `Utiliser un Runfile local` (uniquement si dispo)
- Menu local doit afficher le vrai nom du runfile (si plusieurs fichiers).
- Aide saisie colorée cohérente avec palette existante.

### GUI
- Toujours afficher étapes visibles dans logs, surtout avant lancement install.
- En cas de refus dépendances: statut explicite `Interrompu`.

## 7) Règles de maintenance
- Ne pas réintroduire de logique métier dans TUI/GUI.
- Toute nouvelle règle système/root/dépendance doit être ajoutée en CLI puis consommée via option dédiée.
- Garder les appels bloquants/réseau en thread côté Rust.
- Conserver le parsing robuste des sorties clé=valeur.
- Préserver la compatibilité des options CLI utilisées par TUI/GUI.
